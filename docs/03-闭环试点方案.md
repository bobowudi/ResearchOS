# 调研决策系统 — 闭环试点方案

## 试点目标

用最小闭环验证核心假设：**多源证据融合 + 决策卡 + 行动追踪** 能否真正缩短决策周期、提升决策质量。

## 试点场景：品牌健康度决策

选择"品牌健康度"作为试点场景，原因：

1. 数据源天然多样（问卷 NPS、社媒口碑、竞品动态、销售数据）
2. 决策频率适中（月度/季度），适合验证闭环
3. 与现有 SaaS 项目的问卷能力天然衔接
4. 客户需求明确，容易找到试点用户

## 试点范围

### 接入的数据源（3 个，不贪多）

| 数据源 | 接入方式 | 优先级 |
|--------|---------|--------|
| 问卷数据（NPS/满意度） | 从现有 SaaS 平台 API 导入 | P0 |
| 社媒舆情 | 接入第三方舆情 API（如微博/小红书） | P0 |
| 竞品公开信息 | 定期爬取 + 人工补充 | P1 |

### 核心功能（最小闭环）

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│  创建议题     │ ──▶ │  证据汇聚     │ ──▶ │  生成决策卡   │
│ "品牌NPS下降  │     │ 问卷+舆情+竞品 │     │ 含正反证据    │
│  原因是什么?" │     │ 自动关联       │     │ 置信度标注    │
└─────────────┘     └─────────────┘     └─────────────┘
                                              │
                                              ▼
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│  回看结果     │ ◀── │  追踪执行     │ ◀── │  派生行动项   │
│ NPS是否回升?  │     │ 谁在做?进度?  │     │ 具体做什么?   │
│ 模型校正      │     │ 截止日期      │     │ 谁负责?      │
└─────────────┘     └─────────────┘     └─────────────┘
```

### 功能清单

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 议题创建 | 用自然语言描述要解决的问题 | P0 |
| 多源证据导入 | 从问卷平台导入 + 舆情 API 接入 | P0 |
| 证据自动关联 | AI 将不同来源的证据关联到议题 | P0 |
| 证据冲突标注 | 当不同数据源结论矛盾时高亮提示 | P0 |
| 决策卡生成 | AI 基于证据生成结构化决策建议 | P0 |
| 置信度标注 | 每条证据和决策建议标注可信度 | P0 |
| 行动项派生 | 从决策卡生成具体待办事项 | P1 |
| 执行追踪 | 行动项状态管理（待办/进行中/完成） | P1 |
| 结果回看 | 对比行动前后指标变化 | P1 |
| AI 对话 | 随时用自然语言提问和获取分析 | P1 |

## 试点验证假设

| 假设 | 验证方式 | 成功标准 |
|------|---------|---------|
| 多源证据比单一数据源更有决策价值 | 用户访谈 + 决策卡采纳率 | 采纳率 > 40% |
| 决策卡能加速决策过程 | 对比使用前后决策周期 | 缩短 > 30% |
| 冲突证据展示增强决策信心 | 用户满意度调查 | 满意度 > 4/5 |
| 行动追踪能提升执行率 | 行动项完成率统计 | 完成率 > 50% |
| 闭环反馈能改善后续决策 | 第二轮决策质量对比 | 质量评分提升 > 20% |

## 试点时间线

| 阶段 | 周期 | 交付物 |
|------|------|--------|
| 第一阶段：数据接入 + 证据展示 | 4 周 | 能导入问卷和舆情数据，按议题展示证据 |
| 第二阶段：决策卡 + AI 推理 | 4 周 | AI 生成决策卡，含冲突检测和置信度 |
| 第三阶段：行动追踪 + 闭环 | 3 周 | 行动项管理、结果回看、反馈校正 |
| 第四阶段：试点用户验证 | 3 周 | 3-5 个真实客户使用，收集反馈 |

总计约 14 周（3.5 个月）完成试点闭环。

## 试点技术选型建议

| 层 | 技术方向 |
|----|---------|
| 前端 | Vue 3 + TypeScript（与现有 SaaS 技术栈一致） |
| 后端 | Next.js + Node.js（主业务入口）+ 独立 AI Reasoning Service（Node.js） |
| AI 推理 | Claude API / GPT-4 API（证据分析、决策卡生成） |
| 数据存储 | TiDB（结构化主数据）+ Elasticsearch（检索与语义召回） |
| 舆情接入 | 第三方舆情 API |

## Kill Criteria（停止条件）

如果出现以下情况，暂停试点并重新评估：

- 4 周内无法完成第一阶段数据接入
- 试点用户决策卡采纳率 < 20%
- 用户反馈"不如直接看原始数据"
- AI 生成的决策建议准确率 < 60%
