# ResearchOS 产品设计文档 v1.2

> 本文档只讲产品设计：用户是谁、解决什么问题、有哪些功能、页面长什么样、交互怎么走。
> 技术架构请见《07-架构设计-v1.2.md》。

---

## 一、产品定位

一句话：把散落在问卷、访谈、舆情、报告中的碎片证据，通过 AI 正反辩论，变成"你该做什么"+ 追踪"做了之后怎么样"。

核心差异：不是给你答案，而是帮你把正反两面都摊开，让你在充分信息下自己做判断。

## 二、目标用户画像

### 画像 A：品牌负责人 — 李总监

- 背景：某国产护肤品牌市场总监，管 15 人团队
- 痛点：每月收到 3-5 份研究报告（NPS、舆情、竞品），但报告之间互相矛盾，不知道该信哪个
- 期望：一个地方看到所有证据，AI 帮我理清矛盾，告诉我该优先做什么
- 使用频率：每周 2-3 次，每次 30-60 分钟
- 决策类型：品牌定位、传播策略、竞品应对、预算分配

### 画像 B：产品经理 — 王 PM

- 背景：某 SaaS 公司高级产品经理，负责核心产品线
- 痛点：用户调研做了很多，但每次做决策还是靠"拍脑袋"，调研数据没有被系统性地用起来
- 期望：把历史调研沉淀下来，新决策时能快速调取相关证据
- 使用频率：每周 1-2 次，集中在版本规划期
- 决策类型：功能优先级、用户体验优化、定价策略

### 画像 C：研究团队负责人 — 张经理

- 背景：品牌方内部洞察团队 leader，5 人团队
- 痛点：辛苦做的研究报告，业务方看完就扔了，研究成果无法复用
- 期望：研究成果能被结构化沉淀，下次有类似问题能直接调用
- 使用频率：每天使用，是系统的主要内容生产者
- 决策类型：研究方案设计、数据源选择、洞察输出

## 五、核心功能详细说明

### 5.1 议题管理

| 功能点 | 说明 | MVP 范围 |
|--------|------|---------|
| 创建议题 | 自然语言描述问题 + 选择领域标签 + 设定决策截止日期 | ✅ |
| 议题状态 | 草稿 → 收集证据中 → 分析中 → 待决策 → 已决策 → 已关闭 | ✅ |
| 议题模板 | 预设常见议题模板（品牌健康、竞品应对、新品上市等） | ✅ |
| 议题归档 | 关闭后自动归档，可搜索历史议题 | ✅ |
| 议题协作 | 邀请团队成员参与同一议题 | P2 |

### 5.2 证据管理

| 功能点 | 说明 | MVP 范围 |
|--------|------|---------|
| 数据源接入 | 问卷 API + 舆情 API + 手动上传 | ✅ |
| 自动关联 | AI 根据语义将证据关联到相关议题 | ✅ |
| 人工关联 | 用户手动将证据拖拽/选择关联到议题 | ✅ |
| 证据标签 | 自动生成 + 人工编辑标签 | ✅ |
| 置信度评分 | 基于来源质量/样本量/时效性自动评分 | ✅ |
| 立场标注 | 支持/反对/中立，AI 自动标注 + 人工修正 | ✅ |
| 证据搜索 | 关键词 + 语义搜索混合 | ✅ |
| 证据溯源 | 点击可查看原始数据来源 | ✅ |
| 批量导入 | 一次导入多份文档/数据 | P1 |
| 证据过期提醒 | 超过设定时效的证据标记为"可能过时" | P2 |

### 5.3 对抗性推理与决策卡

| 功能点 | 说明 | MVP 范围 |
|--------|------|---------|
| 一键生成 | 点击"生成决策卡"触发三角推理 | ✅ |
| 正反辩论展示 | 左右分栏展示正方/反方论证 | ✅ |
| 证据引用 | 每条论证关联具体证据，可点击跳转 | ✅ |
| 冲突检测 | 自动识别并高亮矛盾证据 | ✅ |
| 盲区识别 | 标注当前证据未覆盖的重要维度 | ✅ |
| 失败预警 | "如果失败，最可能因为..." | ✅ |
| 置信度评分 | 综合评分 + 影响因素说明 | ✅ |
| 采纳/拒绝 | 必须填写理由（用于模型学习） | ✅ |
| 重新分析 | 补充证据后可重新触发推理 | ✅ |
| 决策卡版本 | 保留历史版本，支持对比 | P1 |
| 决策卡分享 | 生成链接分享给未注册用户查看 | P2 |
| 导出 PDF | 决策卡导出为结构化报告 | P2 |

### 5.4 行动追踪与闭环

| 功能点 | 说明 | MVP 范围 |
|--------|------|---------|
| 自动派生 | 采纳决策卡后 AI 自动建议行动项 | ✅ |
| 人工编辑 | 可修改/新增/删除行动项 | ✅ |
| 责任人分配 | 指定负责人 + 截止日期 | ✅ |
| 状态流转 | 待办 → 进行中 → 完成 → 已验证 | ✅ |
| 回看录入 | 录入实际结果 + 效果评估 + 经验总结 | ✅ |
| 到期提醒 | 截止日期前通知负责人 | P1 |
| 指标对比 | 自动对比行动前后关键指标 | P1 |
| 经验沉淀 | 回看结果自动归入知识库 | P2 |

### 5.5 AI 对话助手

| 功能点 | 说明 | MVP 范围 |
|--------|------|---------|
| 全局侧边栏 | 任何页面右侧可展开 AI 对话 | P1 |
| 证据问答 | "关于卡顿问题，问卷和舆情分别怎么说？" | P1 |
| 议题建议 | "基于最近的数据变化，有什么值得关注的？" | P2 |
| 上下文感知 | AI 知道你当前在看哪个议题/证据 | P1 |

## 六、核心交互流程

### 6.1 从议题到决策的主流程

```
用户创建议题
    │
    ▼
填写议题描述 + 选择领域 + 设定截止日期
    │
    ▼
系统自动拉取相关证据 ←── 用户也可手动添加证据
    │
    ▼
证据面板展示：按来源分组，标注置信度
    │
    ├── 发现冲突？→ 高亮冲突提示，展示 AI 解读
    │
    ▼
用户点击 [生成决策卡]
    │
    ▼
Loading 状态（约 15-30 秒）
展示："正方正在构建论证... 反方正在寻找反驳... 裁判正在综合评估..."
    │
    ▼
决策卡生成完毕，展开显示
    │
    ├── 用户觉得证据不够？→ [补充证据] → [重新分析]
    ├── 用户觉得方向不对？→ [修改议题描述] → [重新分析]
    │
    ▼
用户选择：[采纳] / [修改后采纳] / [拒绝]
    │                                    │
    │ 采纳                               │ 拒绝
    ▼                                    ▼
AI 自动建议行动项                    填写拒绝理由
用户编辑确认                         （用于模型学习）
    │
    ▼
行动项分配责任人 + 截止日期
    │
    ▼
执行期间：状态更新 + 到期提醒
    │
    ▼
行动完成 → 录入回看结果
    │
    ▼
系统生成闭环报告：决策是否有效 + 经验沉淀
```

### 6.2 证据冲突处理流程

```
系统检测到冲突
    │
    ▼
在证据面板中高亮冲突对
    │
    ▼
展示 AI 解读：为什么会冲突？可能的原因是什么？
    │
    ├── 用户认可解读 → 冲突信息纳入决策卡
    ├── 用户不认可 → 可手动标注自己的解读
    └── 用户需要更多信息 → 系统建议补充哪类数据
```

### 6.3 决策卡生成过程（用户可见）

不是黑盒，用户能看到推理过程：

```
Step 1/4  检索相关证据...          ✅ 找到 23 条相关证据
Step 2/4  正方构建支持论证...       ✅ 3 条核心论据
Step 3/4  反方构建反对论证...       ✅ 3 条核心反驳
Step 4/4  裁判综合评估...          ✅ 决策卡已生成

[展开查看完整决策卡]
```

用户可以在任何步骤点击查看中间结果，增强透明度和信任感。

## 七、数据源接入规格

### MVP 支持的数据源

| 数据源 | 接入方式 | 数据格式 | 更新频率 |
|--------|---------|---------|---------|
| 自有问卷平台 | API 对接 | JSON（结构化） | 问卷关闭后自动同步 |
| 第三方舆情平台 | API 对接 | JSON（半结构化） | 每日定时拉取 |
| 手动上传 | 文件上传 | TXT/CSV/Excel | 用户主动上传 |

### P1 扩展数据源

| 数据源 | 接入方式 | 说明 |
|--------|---------|------|
| 访谈记录 | 文本上传 | 支持结构化访谈模板 |
| 竞品信息 | API + 人工 | 半自动采集 + 人工补充 |
| 行业报告 | 文件上传 | 人工上传摘要，不做 PDF 自动解析 |

### 证据标准化规则

无论来源，每条证据入库后统一包含：

```
{
  source_type: "问卷" | "舆情" | "竞品" | "报告" | "手动",
  content: "原始内容或摘要",
  summary: "AI 生成的一句话摘要",
  stance: "支持" | "反对" | "中立",
  tags: ["NPS", "产品体验", ...],
  confidence: 0-100,
  freshness: "2026-03-15",
  citation: "来源引用信息"
}
```

## 九、成功指标

### 产品核心指标

| 指标 | 公式 | 数据来源 | MVP 目标 | 时间窗口 |
|------|------|---------|---------|---------|
| 决策卡采纳率 | 已采纳决策卡 / 总生成决策卡 | 系统日志 | > 40% | 月度 |
| 行动项完成率 | 已完成行动项 / 总派生行动项 | 系统日志 | > 60% | 月度 |
| 证据复用率 | 被 ≥2 个议题引用的证据 / 总证据 | 系统日志 | > 20% | 季度 |
| 用户周活跃率 | 周登录用户 / 总注册用户 | 系统日志 | > 50% | 周度 |
| 议题闭环率 | 走完全流程的议题 / 总创建议题 | 系统日志 | > 30% | 月度 |

### 对抗推理质量指标

| 指标 | 公式 | 数据来源 | 目标 |
|------|------|---------|------|
| 反方论证有效率 | 用户标记"有价值"的反方论点 / 总反方论点 | 用户反馈 | > 60% |
| 盲区命中率 | 用户确认"确实重要"的盲区 / 总标注盲区 | 用户反馈 | > 50% |
| 冲突检测准确率 | 确实矛盾的冲突 / 总标注冲突 | 人工抽检 | > 70% |

### 护栏指标（不能变差）

| 指标 | 红线 | 触发动作 |
|------|------|---------|
| 决策卡生成失败率 | > 10% | 排查 AI 服务稳定性 |
| 证据关联错误率 | > 20% | 优化关联算法 |
| 页面加载时间 | > 3 秒 | 性能优化 |
| 用户投诉"AI 胡说八道" | > 5 次/周 | 紧急优化 prompt |

## 十、Kill Criteria

如果出现以下情况，暂停并重新评估：

- 4 周内无法完成数据接入闭环
- 决策卡内部评审通过率 < 50%
- 试点用户决策卡采纳率 < 20%
- 用户反馈"不如直接看原始数据" > 50%
- AI 推理成本 > ¥5/次决策
